# SevenWriter 三人评审机构

每次评审从 SevenWriter 自有评审员库中抽取三人。每位评审员拥有原创姓名、固定职能、固定专业侧重和固定适用场景；不会为了当前任务临时更换身份。姓名、职能和本次场景任务公开，不使用外部材料中的人物姓名、人设、“世界观”或原评语。

## 三类必备职能

### 事实与边界席

核对事实、数字、时间、限定语、引用、未知项、关键词和结构契约。发现实质错误时行使否决权；其他两席和综合分不能抵消。

### 场景与读者席

检查内容是否适合目标读者、关系、渠道和行动目的。根据 SEO、GEO、邮件、社交、口播、演讲或长文 profile 调整检查项，不套统一营销标准。

### 表达与文风席

检查自然度、信息密度、逻辑、节奏、可读性和样文匹配。不得用错别字、生僻词和随机句长制造“真人感”。

## 随机成员，强制覆盖

评审员库分为事实与边界、场景与读者、表达与文风三组。系统先按当前场景过滤有对应专长的成员，再从每组随机抽取一人，因此恰好三人，并始终覆盖三类基础职能。通用成员可进入任何场景，专业成员只进入其固定场景。随机种子写入评审记录，允许复现本次组团。每名成员在固定专长内加载本场景议题，不能把某一场景的标准泛化到全部写作：

- SEO/GEO：事实席检查实体、来源、链接和关键词；场景席检查意图、答案和信息增益；表达席检查可扫描性与关键词自然度。
- 客户/售后：事实席检查状态、金额、政策和承诺时间；场景席检查问题是否被回答及下一步；表达席检查是否清楚、克制、没有推诿或客服套话。
- 社交/产品推荐：事实席阻止伪亲测和虚假效果；场景席检查对象、平台和转化目的；表达席检查自然度但不强行口语化。
- 短视频/演讲：事实席核对故事和数据；场景席检查时长、开场、递进和行动；表达席负责朗读、停顿和听觉重复。
- 长文/网站：事实席维护跨节一致性；场景席检查主线、页面目标和信息层级；表达席检查段落推进与风格统一。
- 播客/PPT/个人简介：事实席核对人物、引语、数字和来源；场景席检查听众、时长与单元任务；表达席检查听觉节奏、页面负担或身份语体。
- 周报/协议/学术：事实席核对进度、条款、数据与引文；场景席检查执行目的、论证链与待确认项；表达席检查术语、指代和结构一致性。
- 游戏/合规：事实席核对玩法、权利、证据与监管限定；场景席检查平台、地区、受众与发布风险；表达席保留披露和限制，不以润色掩盖风险。

当任务具有更细的子场景时，以子场景议题优先；没有匹配项时回退到通用议题。

## 评审流程

1. 根据当前场景建立必备检查项，并记录随机种子，从三个能力组各抽取一名评审。
2. 写作端根据同一内容契约生成最少必要候选。
3. 评审端临时将候选标记为 A/B/C，不显示生成策略、模型、原始分数和上一轮赢家。
4. 三人分别提供证据位置、0–5 分、置信度和 failure tags，并说明为什么是这个分数。
5. 每个问题必须尽量给出位置、原句、问题、原因、建议改法和验证方式；只有存在可靠局部替换时才给参考改文，不能为凑格式编造句子。
6. 事实职能评审可否决；其余候选计算三人置信度加权均分。
7. 与 SevenWriter 原 100 分 rubric 合并：确定性/启发式质量分占 70%，三人语义评审占 30%。
8. 分差低于 2/100 时选择改动更少的候选。
9. 冲突意见原样保留，不让模型虚构共识。

## 生成与评审隔离

最佳方案是使用独立评审模型或独立调用。只有一个模型时，至少使用新上下文、临时候选编号和结构化 rubric。评审只评价，不直接改稿；修复器根据 failure tags 另开一轮。
