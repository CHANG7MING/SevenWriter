# 文档模式

## 流程

1. 解析文档，建立标题层级、段落、列表、表格、引用、链接、代码和元数据地图。
2. 全局提取：目标读者、语体、术语表、事实锁、重复观点、章节作用。
3. 按语义章节切分；保留前后 1 段摘要作为上下文。
4. 逐节改写，记录术语、承诺、人物称谓与时态。
5. 合并后检查跨节重复、指代、标题风格、术语和结论一致性。
6. 比对结构地图与内容契约，再输出新文件。

## Markdown

不得改写 fenced code block、inline code、URL、frontmatter 键、HTML 标签和表格结构，除非用户明确要求。链接文字可改时仍保持目标 URL。标题是否可改由内容契约决定。

## Word

优先使用宿主提供的 Word/.docx 工具以保留样式和结构。无法确认无损时，先导出结构化文本或 Markdown 供审阅，不覆盖原文件。页眉页脚、批注、修订、脚注、文本框和嵌入对象需单独检查。

## 长文一致性

维护一个轻量 ledger：实体名、术语首选写法、关键数字、时态、称谓、CTA、各节结论。章节完成后更新，最终全局复核。
